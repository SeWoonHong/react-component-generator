# TDD Rule

> **이 규칙은 Rigid — 상황에 맞게 변형하지 마라.**
> 적용 대상이면 예외 없이 아래 사이클을 그대로 따른다. 단계를 건너뛰거나 합치거나 순서를 바꾸지 않는다.

## 우선순위

- 프로젝트의 `CLAUDE.md` / `AGENTS.md`(하위 디렉토리 포함)에 TDD 규칙이 있으면 **그 규칙이 우선**한다.
- 이 파일은 그런 규칙이 없을 때 쓰는 **기본값(fallback)** 이다.
- 테스트 실행 명령은 프로젝트 문서를 따른다. 이 저장소는 `bun run test` (`bun test` 아님).

## 적용 기준

### 반드시 적용

- **비즈니스 로직**: 계산, 상태 전이, 검증, 분기 규칙
- **API**: 엔드포인트의 요청 검증, 응답 형태, 에러 처리
- **유틸 함수**: 파싱, 변환, 정규화, 포매팅
- **버그 수정**: 버그를 재현하는 실패 테스트를 **먼저** 작성한 뒤 고친다
- 위 대상을 담은 UI 컴포넌트의 **동작**(입력 → 콜백, 활성/비활성, 조건부 렌더링)

### 불필요

- **타입 정의**: `type`, `interface`만 있는 파일
- **설정 파일**: 빌드·린트·tsconfig·환경 설정
- **순수 UI**: 동작 없는 마크업, 스타일, 레이아웃, 문구 변경
- **SQL**: 스키마·마이그레이션 정의

판단이 애매하면 **적용 대상으로 본다.**

## RED-GREEN-REFACTOR

### 1. RED — 실패하는 테스트 작성

- **하나의 동작 = 하나의 테스트.** 한 테스트에 여러 동작을 몰아넣지 않는다.
- 테스트 이름은 검증하는 동작을 문장으로 쓴다.
- 작성 후 **반드시 실행해서 실패를 눈으로 확인**한다. 실행하지 않은 RED는 RED가 아니다.
- 실패 이유가 **"기능 미구현"** 이어야 한다 (기대값 불일치, 함수 없음 등).
  - 오타, import 경로 오류, 문법 오류, 테스트 설정 문제로 실패했다면 RED가 아니다. 테스트를 고쳐서 올바른 이유로 실패할 때까지 반복한다.
- 처음부터 통과하는 테스트는 아무것도 검증하지 못한다. 테스트를 다시 작성한다.

### 2. GREEN — 통과시키는 최소 코드

- 지금 실패하는 테스트를 통과시키는 **최소한의 코드만** 작성한다.
- **YAGNI**: 다음에 필요할 것 같은 인자, 옵션, 추상화, 분기를 미리 넣지 않는다.
- **신규 테스트와 기존 테스트가 모두 통과**하는 것을 실행해서 확인한다.
- 기존 테스트가 깨졌다면 GREEN이 아니다. 테스트를 고쳐서 맞추지 말고 구현을 고친다.

### 3. REFACTOR — 동작은 그대로, 구조만 개선

- 대상: **중복 제거, 이름 개선, 헬퍼 추출**, 테스트 코드 정리.
- 변경마다 테스트를 실행해 **green을 유지**한다. 깨지면 즉시 되돌린다.
- **새 동작 추가 금지.** 새 동작이 필요하면 다음 RED에서 시작한다.

### 4. 반복

- 다음 동작을 하나 골라 **RED로 돌아간다.**
- 구현할 동작이 남지 않을 때까지 1 → 2 → 3을 반복한다.

## 삭제 강제 규칙

- 테스트보다 프로덕션 코드를 먼저 작성했다면 **그 코드를 삭제하고 RED부터 다시 시작한다.**
- **"참고용"으로 남기는 것도 금지한다.** 주석 처리, 별도 파일·브랜치 보관, 붙여넣기용 기억 모두 포함.
- 삭제 후 다시 쓰는 코드는 테스트가 요구하는 만큼만 작성한다 (GREEN 규칙 그대로 적용).

## 변명 차단표

| 변명 | 반론 |
|------|------|
| "너무 단순해서 테스트 불필요" | 단순하면 테스트도 1분이면 끝난다. 단순한 코드가 깨지는 순간이 가장 찾기 어렵다. |
| "나중에 추가하겠다" | 나중에 쓴 테스트는 구현에 맞춰 통과하도록 쓰여서 아무것도 검증하지 못한다. 그리고 나중은 오지 않는다. |
| "시간이 없다" | 테스트 없이 아낀 시간은 디버깅과 회귀 수정으로 더 크게 돌아온다. 시간이 없을수록 범위를 줄이고 TDD는 유지한다. |
| "삭제하면 낭비" | 이미 쓴 코드는 매몰 비용이다. 테스트로 설계를 다시 하면 대개 더 짧고 정확해진다. 남겨두면 테스트가 그 코드를 정당화하는 방향으로 쓰인다. |
| "프로토타입이다" | 프로토타입은 거의 그대로 프로덕션이 된다. 정말 버릴 코드라면 적용 대상 판단부터 다시 하고, 남길 코드라면 TDD로 쓴다. |
